## 一、口径（2026-09-14 用户定案）

1. **视觉基准 = 参考版截图**：一比一以参考版（`io.legato.kazusa`）实机截图为准；参考版本身基于原版 UI 改动，且与我方同为 Flutter 系，对齐成本最低。
2. **功能基准 = 双基准不变**：原版 Kotlin 源码（legado-upstream）+ 参考版任一侧存在即应有能力（2026-09-11 口径延续）。功能行为分歧时以原版源码裁决，视觉形态以参考版裁决。
3. **配色与字体一并纳入一比一**（**废止 2026-08-05「UI 视觉风格自由」授权**）：颜色、字体、明暗主题均须对齐参考版。此为用户在明确告知工作量与回归风险后的主动选择。
4. 实现层仍遵循 Material Design 3（参考版即 M3 风格），主题体系改造按本规范推进，[UI_MD3_PLAN.md](UI_MD3_PLAN.md) 中与一比一冲突的条目以本规范为准。

## 二、比对维度（每屏逐项核对）

| 维度 | 核对内容 |
|---|---|
| 布局骨架 | 页面结构（顶栏/ body / 底栏/ FAB / 弹层形态）、滚动容器 |
| 位置与层级 | 元素排布顺序、对齐方式、层叠关系（含徽标/角标） |
| 间距与尺寸 | 页边距、元素间距、控件高度、图标尺寸、封面比例 |
| 圆角与形态 | 卡片圆角、描边、阴影水位、控件形状（胶囊/圆角矩形） |
| 图标与文案 | 图标选形（含实心/描边）、文案措辞、字号字重 |
| 配色与字体 | 主题色槽位、表面/容器色、字体族与字号阶梯（明暗两态各自核对）。**缺口登记（2026-09-14 自查）**：现有参考归档全部为浅色主题，深色主题参考截图须补采后暗色比对方可覆盖；正文排版默认值（字号/行距/边距/缩进）一并纳入比对范围 |
| 状态形态 | 空态/加载态/错误态/选中态/禁用态的呈现 |

允许保留的差异（登记即可，无需修改）：系统状态栏/导航栏由系统渲染的部分、屏幕分辨率引起的亚像素差异、平台能力差异（如 Android 原版特有权限弹窗）。

**多态屏约定**：一屏多状态的（如搜索结果=搜索中/已完成，书架=有书/空态/多选），每个状态单独截图单独登记，台账行内注明已覆盖状态与缺口状态。

**版本标注约定**：我方截图目录带版本号（`ours_<版本>/`），参考截图目录带日期（`ref_<YYYYMMDD>/`）；pairs 索引须注明我方版本，版本升级后未复验屏保留旧 pair 并标注过期。

## 三、工作流（每屏六步 + 分工）

**分工（2026-09-14 子代理恢复后定案）**：
- **子代理（并行上限 2）**：全部执行操作——工具脚本开发、代码修复、构建、冒烟、adb 导航脚本编写。
- **主代理**：任务拆解与审核、diff 复核验收、文档与提交；**图片环节专属**——截图采集执行、截图目视比对、差异裁决与登记（子代理无视觉能力，禁止派发图片判断类任务；采集脚本中 dump 文本断言类导航可由子代理编写，脚本执行与核图归主代理）。
- **禁兜底照旧**：子代理失败须报告并经用户同意后方可主代理接手。

每屏六步：

1. **截图配对**：参考版与我方各截一组（同分辨率、同场景状态、明/暗两态按需），归档至 `docs/parity_shots/`。
2. **逐维比对**：按 §二 七个维度逐项核对，差异逐条登记台账（含截图坐标/元素名证据）。比对辅助：`scripts/parity_pair.py`（并排拼图 + 差分热图 + 差异像素占比，子代理开发、主代理核图）。
3. **修复实施**：按台账逐条修；主题/配色类改动须走主题槽位（AppColors/AppTheme），禁止散落硬编码色值。
4. **复验**：修复后重新截图配对，与基准并排核对，逐条销差异。
5. **闭环登记**：台账状态改「闭环」+ 版本号；重大口径变化回写本规范。
6. **提交纪律**：照旧（约定式提交、版本递增、双更新日志同步、冒烟通过）。
