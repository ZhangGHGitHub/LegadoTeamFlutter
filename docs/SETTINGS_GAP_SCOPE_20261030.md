# 设置页面对齐参考版——缺口盘点与修改范围（2026-10-30）

> 编写：ZCode 主代理 ｜ 2026-10-30
> 依据：参考版 `legado-with-MD3`（Compose/MD3，视觉与功能目标）、Android 原版 `legado-upstream`、我方 `flutter_legado` 全量源码对照（两路只读调研）。
> 本文只确定「改什么、分几批、依赖与裁决项」，不含实现。

## 一、总体结论

1. **设置主链路已具备**（我的 → 设置主页 → 外观/其他设置/备份恢复/关于），但设置主页 **参考版 11 个入口、我方 9 个**，缺「下载与缓存、封面设置、AI 设置、翻译设置、隐私、实验室」6 个入口。
2. **整页/整面板缺失 7 类**：独立阅读设置页、阅读器「菜单系统」页、护眼模式配置、朗读设置页、书架布局配置页（我方 3 项 vs 参考版约 40 项）、书签标记样式、封面设置独立页+封面相册。
3. **设置项级缺口约 40+ 项**，集中在外观（容器背景/边框/分隔线/护眼/多栏）、其他设置（自启动/电池优化/更新）、备份（同步模式/忽略列表）、阅读（字体/标题/下划线/点击区域/底栏图标）。
4. **最值得先修的是「有开关无功能」**：13 项偏好写入后无消费方（抗锯齿、图片缓存、漫画保留数、预下载数、线程数、源编辑最大行数、自动清除过期搜索、漫画浏览、自动更新、耳机按键三件套、Web 服务唤醒锁、UserAgent 仅 RSS 生效、语言仅 AppStrings）。
5. **参考版独有项**（原版无）占比不小：导航 Sheet/多栏、护眼、容器背景、封面相册、菜单系统/毛玻璃、阅读锚点、分段标题、AI/翻译/实验室。补齐即扩展功能面，本文件按用户「对比参考版补齐」授权纳入，但 AI/翻译/实验室需 Rust 能力，单独裁决。

## 四、视觉/交互差异（影响较大的）

1. 参考版分组用「拼接卡片组」（组内行、仅组首尾圆角），我方逐行 ListTile → 页面更长、层次松散。建议抽 `SplicedColumnGroup` 等价组件，统一设置页。
2. 数值项参考版是「标题+滑块+数值+步进」行内控件；我方多需点开对话框（已影响 6 处）。
3. 点击区域参考版 3×3 宫格可视化；我方下拉三选一。
4. 阅读样式参考版横排卡片条+长按编辑；我方独立主题页（能力更全、路径更长）。

## 六、需用户裁决

1. **隐私页范围**：最小版（本地密码/通知/电池/入口壳，约 1d）先上，还是必须含「书籍/分组私密标记+生物识别+解锁策略」（需 Rust/DB 新模型，5–8d）？
2. **AI/翻译/实验室**：参考版有、Rust 无对应能力。是否本期只做设置 UI 占位（明确禁用并提示待支持），还是单独立 Rust 批（5–10d+）？建议先不做占位入口，避免「可点不可用」。
3. **应用字体入口**：参考版外观页有「字体设置（应用字体）」，与此前 N6 裁决（字体入口收起）冲突；是否恢复？
4. **设置主页「缓存管理」**：参考版「下载与缓存（设置）」与「缓存管理（我的页）」并存；我方现入口指向任务列表。补 P-1 时是新增「下载与缓存」入口并保留现入口，还是改指设置页？
5. **检查更新查找版本（updateToVariant）**：参考版恢复、原版长期注释；当前更新通道是否需要？
6. **视觉层级**：是否按参考版把设置页统一成「拼接卡片组 + 行内滑块/步进」控件（影响所有设置页，约 2–3d 额外），还是功能优先、保留现 ListTile 形态？

## 七、建议执行顺序

第一批做「接线 13 项 + 独立阅读设置页」，收益最大且不依赖 Rust；第二批做外观/导航/多栏；第三批起按上表推进。渲染依赖强的（标题效果/分段标题/高亮富样式）与 Rust 轨能力（书源 UA、线程数、预下载、隐私、AI/翻译）需要先补能力再接 UI，避免再产生「有开关无功能」。
