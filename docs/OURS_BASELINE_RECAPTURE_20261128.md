## 5. 失败项与原因（诚实登记）

1. **1-10 深色态未采到（唯一缺项）**
   - 现象：`cmd uimode night yes` 后重采阅读器，PNG **字节数完全相同**（366476 B，`05_reader.png` 同尺寸同体积），即阅读器**主题独立于系统夜间模式**，不受 `night yes` 影响。
   - 要拿到深色正文，需进入阅读器内的「阅读界面/背景主题」改用户阅读主题（会持久化改用户偏好，且需逐级展开面板）。本轮未完成，**不声称已采**。
   - 替代证据：`ours_dark_20260920/10_reader.xml` 为旧轮次的深色阅读器基准（2.0.x 早期），仅供形态参考，不能当 2.0.514 证据。

2. **1-3「四分组 tab」未造数**
   - 本机**无用户自定义分组**，分组 tab 行只回落到单一「全部」（与旧基线 2.0.264 图同状态）。
   - 已尝试的替代路径：⋮ → 按来源分组，结果为**按来源分节列表**（见 `01b_shelf_group_by_source.png`），**不生成多 tab**。
   - 造数受阻点：新建分组需在「分组管理」里输入中文组名，本机 `input text` 无法输入中文（无 ADBKeyboard）。
   - 补充证据：多 tab 渲染由单测覆盖，本轮实跑
     `flutter test test/widget/bookshelf_tab_alignment_test.dart` → **2 个用例全通过**
     （「单组（空态回落）：唯一 tab 左对齐」「多组：首 tab 左对齐且各 tab 顺排」），
     即多 tab 的**布局契约有测试保证**，缺的只是真机截图。

3. **全部 9 份 dump 无文字节点（`text=` 计数 = 0）**
   - 根因：设备无任何 AccessibilityService（`pm list packages | grep talkback` 为空，`enabled_accessibility_services=null`），
     Flutter 语义树不生成，`uiautomator dump` 只能拿到空壳 View 结构。
   - 已试：`settings put secure accessibility_enabled 1` → 仍无文字（该开关单独不足以驱动 a11y 连接），已复原为 0。
   - 影响：菜单项/按钮清单改由 **PNG 目视 + 代码常量（`tooltip`/`_CardMenuItem` 文案）交叉核对**得出，
     判定依据可复现（§3 已标注来源）。
   - dump 仍有价值：根节点 `package` 用于归属反证（§1），节点 bounds 可用于点击坐标核对。

4. **环境级差异（会干扰逐像素比对，非缺陷）**
   - 新图无系统状态栏、分辨率 1080x1920（旧图 720x1280 带状态栏）。
   - 书籍数据不同（2+1 本 vs 1 本）。
   - 因此 §4 的差异描述一律以「结构/控件/文案」为单位，不做像素级比对。

## 6. 复现要点（含显示映射的正确做法）

```bash
ADB="/d/Program Files/MuMuPlayer/nx_main/adb.exe"      # adb 不在 PATH
DEV=192.168.100.63:5555
export MSYS_NO_PATHCONV=1                              # 所有 /sdcard 路径必须
```

1. **定位应用所在 logical display**
   `adb shell dumpsys window displays | grep -E 'Display: mDisplayId|mCurrentFocus'`
   → 取 `mCurrentFocus` 含 `io.legado.flutter_legado` 的那一段的 `mDisplayId`（本轮为 5）。
   **`am start --display 0` 无效**：应用固定落在 MuMu 副屏（slot 号会轮转），不要试图拉回 display 0。

2. **logical → physical（唯一权威）**
   `adb shell dumpsys display | sed -n '/mViewports/,/mDefaultDisplay/p'` → 按 `displayId=N` 找
   `uniqueId='local:<physId>'`，**去掉 `local:` 前缀**即为 `screencap -d` 实参。
   **禁止**用 `dumpsys SurfaceFlinger --display-id` 的输出顺序去对应（本轮 logical 5 ↔ SF `HWC display 4`，错配）。

3. **截屏 + 归属反证**
   `adb shell screencap -p -d <physId> /sdcard/x.png` → `adb pull /sdcard/x.png "D:\...\x.png"`
   （pull 本地目标必须写 **Windows 路径**）；随后 `uiautomator dump` 并核对根节点 `package`。

4. **灰度校验（每次必做，坏图尺寸/体积都正常）**
   `.tmp/gray.py`（PIL 16×16 缩放）→ 浅色 `lum>200`、深色 `lum<90`、`min≠max`。

5. **输入必须带 display**
   `adb shell input -d <logicalId> tap x y`（不带 `-d` 会落到 display 0 的桌面）。
   长按用 `input -d N swipe x y x y 900`（该机型无 `input longpress` 子命令）。

6. **清场**
   `cmd uimode night auto` → `am force-stop io.legado.flutter_legado` → `rm -f /sdcard/*.xml`（本轮已执行，
   复核：`ls /sdcard/*.xml | wc -l` = 0，`pidof io.legado.flutter_legado` 空）。
