## 三、核心判定

### 3.1 结论

**参考版 3.26.19 的外观页顶部，手机示意图主题预览仍然存在。**

因此：我方 2.0.269 的删除属于**误删**，**R50 应恢复**该组件（对齐参考版）。

### 3.2 视觉证据

`docs/parity_shots/ref_2.0.514_round2_20261128/ref_3.26.19_appearance_top.png`：

- 标题「外观」下方，紧接着是一个居中的手机示意图：圆角机身 + 蓝色细描边、顶部深色胶囊开孔、机身内一块浅蓝「封面」圆角矩形（右上角带小深色方块）、底部浅灰条内一个深蓝圆形按钮。
- 该预览下方**直接**是「主题模式」分区标题，中间没有任何说明卡片。

与 2026-09-16 旧图（`ref_batch3/04_appearance.png`）对比，做模板匹配（Pillow 灰度、均值绝对差）：

```
template = 新图预览区 bounds [348,384][732,1152]，384x768
best match in 旧图: offset (348,456)
meanAbsDiff = 0.79 / 255
```

判定：**像素级同一控件**（尺寸完全一致 384x768，仅整体纵向位置比旧图高 72px），不是「另做了一个相似组件」。

### 3.3 文本侧证据（dump 层）

`ref_3.26.19_appearance_top.xml` 中，预览区（y 380~1240）只有一个节点：

```
class=android.view.View
bounds=[348,384][732,1152]
clickable=false    text=''    content-desc=''    resource-id=''
```

**该预览没有任何 text 与 content-desc**。这解释了 B3-C1 的判定为何出错：按「外观预览」等文案 grep `resources.arsc` 必然零命中，因为控件本来就不带文案标签。**「grep 不到文案」不等于「功能不存在」。**

## 五、复现要点

1. adb 端点每次实测（`adb devices`），本次为 `192.168.100.63:5555`；adb 用 `"/d/Program Files/MuMuPlayer/nx_main/adb.exe"` 绝对路径（不在 PATH）。
2. 所有 `/sdcard` 路径必须带 `MSYS_NO_PATHCONV=1`，否则 Git Bash 会把 `/sdcard/x` 改写成 `D:/Program Files/Git/sdcard/x`。
3. 启动参考版后先 `dumpsys window displays | grep -E "Display:|mCurrentFocus"` 找承载 kazusa 的 logical displayId；本次为 7。
4. 再从 `dumpsys display` 的 `mViewports` 段取该 logical 对应的 `uniqueId` 尾部数字（本次 `4619827052952829958`），用作 `screencap -d` 的参数。**不要用 SurfaceFlinger 顺序，也不要用 logical id 直接截图（会 Status: -2 失败）。**
5. `input` 事件注入用 logical id（`input -d 7 tap x y`）；`screencap` 用物理 uniqueId。两者不是同一个数字。
6. 每帧必须做根包反证（dump 根节点 `package`）与灰度校验（浅色态 meanLum 应 > 200，全黑图约等于 0）。
7. 参考版包名 `io.legato.kazusa`，包内 Activity 为 `io.legado.app.ui.main.MainActivity`；`monkey -p io.legato.kazusa` 可直接拉起。
