# Legado 重构统一实施流程

> 生效日期：2026-09-27
> 本文规定重构任务如何进入、派发、实施、验证和关闭。当前任务与进度只登记在 [REFACTORING_ACTIVE_PLAN.md](REFACTORING_ACTIVE_PLAN.md)。
> 本次统一依据用户确认：先完成书籍阅读主流程（含搜索和书架），再推进其他既有功能；漫画/视频先于音频；参考版作为用户可见行为目标；可见行为与 Android 原版或已确认规则有差异时先向用户确认；开发修改由指定 Agent 执行。

## 2. 重构目标和差异裁决

1. 第一阶段完成书籍阅读闭环：搜索、书架、加书/开书、详情、目录、正文、翻章、换源、离线缓存、进度保存与恢复。
2. 书籍主流程后推进其他现有功能；媒体顺序为漫画/视频，然后音频。具体开放项仍须进入 Active 计划并按证据排序。
3. 参考版是页面、交互和用户可见结果的实现目标；Rust + Flutter 是当前实现架构，不为复刻参考版内部结构而整体改架构。
4. 若参考版与 Android 原版或用户已确认规则在功能行为上实质冲突，暂停相关任务并向用户提交差异、复现/截图证据、影响范围和推荐选项。不得自行选择；其他互不依赖的工作可以继续。
5. 不新增未经授权的 Android 原版不存在功能，不删除 Android 原版双轨代码，不隐式实施不可逆数据库迁移。
6. 不以“零 TODO/桩”“全部完成”或百分比作为完成依据。完成状态须限定范围、HEAD/提交、测试或验收证据。

## 3. 状态定义和任务记录

每个任务在 Active 计划中只能有一个当前状态：

| 状态 | 使用条件 |
|---|---|
| 待核验 | 仅有历史登记或推测，尚未证明当前 HEAD 存在问题 |
| 已确认待修 | 当前实现可复现失败，需求与验收已明确 |
| 实施中 | Agent 已接单且工作范围、分支/文件边界清楚 |
| 待复验 | 代码已完成，所需 CI、设备、截图或评审证据尚未齐全 |
| 待用户素材 | 工程路径可继续，但真实验收缺账号、样例或硬件 |
| 待用户裁决 | 参考版、原版或既有规则冲突，或涉及未确认取舍 |
| 已关闭 | 代码/文档落点与必要验证证据齐全，验收范围已经写清 |
| N/A | 经核查确定不适用，并记录理由和证据 |

每条登记包含：唯一编号、优先级及用户影响、目标行为、当前实现路径、原版/参考版来源、复现或截图证据、依赖和非目标、执行 Agent、验收条件、验证命令/测试、提交号和剩余限制。专题报告可详细描述证据，但不能另维护一个与 Active 冲突的“当前状态”。

## 4. Agent 分工和任务派发

- **主 Agent**：拆解任务、选择优先级、划定文件边界、派发、跟进、复核 diff 和证据、决定是否验收、维护 Active/索引并处理提交。按用户约定不自行接手子代理的编码、构建或设备取证；Agent 阻塞时先汇报并等待用户决定。
- **`full-stack-engineer`**：执行代码或一般项目文档修改，返回提交、自测输出、变更路径和未完成项。
- **`QA-engineer`**：仅承担 CI 覆盖不到的真实设备流程，提交脚本退出码和日志/证据路径。
- **`UI-operator`**：承担布局/交互改动的截图采集或 UI 操作证据；按项目视觉规范由主 Agent 复核差异。
- **`code-reviewer`**：跨模块、FFI 契约、公共 API、大范围重构或超阈值 diff 必须在提交前评审；仅发送最小 diff 和必要上下文。
- **`debug-engineer`**：问题存在但 CI/本地不能复现根因时，负责最小复现和根因分析。
- **`Researcher`**：仅在新依赖、技术选型、大范围调研或依赖梳理时派发，并要求来源证据。

同一时间最多两个子代理并行。并行任务必须文件和模块边界互斥；猎捕任务不得与修复任务同时写同一文件。不得派代理重复执行 CI 已覆盖的常规门禁。

### 派发给执行 Agent 的任务卡

```text
任务编号与优先级：
目标行为/可复现问题：
当前 HEAD 与证据：
原版/参考版依据：
允许修改路径：
禁止修改路径与非目标：
实施边界及依赖：
验收条件：
必须新增/运行的测试：
设备或素材要求：
契约、DB、codegen、版本和文档同步要求：
交付：变更摘要、diff/提交、测试命令及结果、证据路径、遗留风险
遇到差异/阻塞时：停止该项并提交选项，不得扩大范围或自行裁决
```

## 5. 单个任务的执行门

### 门 A：立项和复核

1. 从 Active 计划选取任务，确认编号未重叠、状态未过时、修改路径无未提交用户工作。
2. 查当前源码、调用路径、现有测试、关闭提交和历史审计；先排除已修、误报或 N/A。
3. 记录实际用户影响并按主流程阻断、主流程严重干扰、一般功能/视觉差异、低优先级维护排序。
4. 写清成功条件、失败条件、范围边界、回滚点和所需证据。条件不明确时不派实施任务。

### 门 B：复现和设计

1. 逻辑问题优先先写能在当前代码失败的测试；UI 问题先准备参考版与我方同状态截图；性能问题先分段计时。
2. 用固定 JSON/HTML/JS 样本和 localhost loopback 测网络、书源与异步边界，避免必需测试依赖真实网站。
3. DB 工作先检查 schema、旧库兼容、事务边界、迁移幂等、备份和失败恢复。
4. 若涉及 FFI、公共 API、跨模块或不可逆改动，先冻结契约/方案并触发提交前评审。
5. 参考版与 Android 原版或明确规则有实质冲突时进入“待用户裁决”，不进入实施门。

### 门 C：实施

1. Agent 只修改任务卡授权路径；额外发现另建任务，不顺手扩散修改。
2. 一批围绕一个根因或紧密关联行为；不把视觉、解析、DB schema 和依赖升级混成单批。
3. Flutter UI 任务可先用 Mock 开发交互；Mock 通过不证明真实 FFI、DB 或书源正确。
4. FFI 变更顺序固定为：更新 `API_CONTRACT.md` → BookApi/RustApi/Mock → Rust 实现 → 同一次 FRB codegen 生成 Dart/Rust → 重编相应 native library → hash/契约核对 → 双端验证。禁止手改生成文件。
5. DB 变更必须提供旧库升级、重复打开、迁移中断/恢复和关键数据保留证据；不可逆项明确标出并先评审。

### 门 D：验证与实机

1. 先跑新增回归测试，再运行受影响模块的原生测试；随后使用 Rust、Flutter 或 Android 对应 CI 门禁。
2. `flutter_legado/**`、`rust/**` 的常规分析和测试以 CI 结果为准；不重复派角色跑同一验证。
3. 只在 CI 覆盖不到的 UI 交互、生命周期、平台差异和真源验收上执行设备测试。
4. 每次设备任务先探测当前 MuMu 在线实例、ADB 端点、guest 网络、设备尺寸、目标包和 debug/release 变体，不假设固定端口可用。设备不可用时登记阻塞，不切回已弃用雷电档。
5. 视觉验收需同屏幕状态、同尺寸、同主题，记录参考截图、我方截图、差异点和复验结果；仅有主题 token 或 widget 测试不等同逐屏闭环。
6. 任何失败都记录原始失败、复现条件和处理结果；不得把一次偶发通过或 Agent 自述当作独立证据。

### 门 E：验收、提交与关闭

1. 主 Agent 确认 diff 未越界、测试对应当前改动、截图/日志来自正确设备与版本、结果符合验收条件。
2. 高风险改动确认有 `code-reviewer` 结论后方可提交；一般小修不强制评审。
3. 按项目 Conventional Commit 规范提交；代码批次按规则同步版本、CHANGELOG 和应用内更新日志。文档批次按文档署名与日期规则办理。
4. 关闭 Active 项时记录提交/CI/测试/QA/截图证据及限制。工程完成但外部素材缺失时，只关闭工程部分，验收仍为待素材。
5. 阶段结束核对 Active、专题证据、docs 索引与 Git 状态；下一阶段只从 Active 开放队列启动。

## 6. 总体阶段与进入/退出条件

不设置固定日历周。每一阶段必须通过退出条件才转下一阶段；可并行的只限已拆分且不共享文件、契约或设备的工作。

| 阶段 | 顺序和工作范围 | 退出条件 |
|---|---|---|
| **0 进度校准** | 核对 Active、阅读缺陷表、浅色/深色 parity、剩余风险和当前 HEAD；先处理重复、过时和相互矛盾状态。特别核 B-10/B-11、B-13、P2-20。 | 当前任务有唯一编号与状态；历史数字不再冒充当前结论；需复验/裁决/素材的项已分开登记。 |
| **1A 搜索和书架** | 搜索流、分页、取消、空态/失败；加书、书架刷新/分组/排序、书架开书。 | 搜索与书架状态一致；旧请求不覆盖新状态；关键空/错/有数据形态有测试。 |
| **1B 目录和换源** | 目录本地/网络加载、刷新、章节定位、分页、换源成功/失败/取消。 | DB 与 UI 的书籍键、目录、进度和派生字段一致；取消不提交半成品。 |
| **1C 正文和进度** | 正文缓存、翻章、快速连续操作、后台保存、退出与重进恢复、清缓存。 | 章节内容/进度一致；数据写入和恢复可重复验证；设备复验项有证据或显式阻塞。 |
| **2 书籍周边能力** | 与书籍链路直接相关的书源管理、规则解析、QuickJS、网络行为，按真实命中及可复现性逐项推进。 | 每个兼容能力有来源语义、fixture、回归结果和明确的平台边界；不追求机械模拟完整 JVM。 |
| **3 其他现有功能和视觉** | RSS、设置、备份、Web 等既有能力；重算浅色缺采，逐步采集和验收暗色屏。 | 功能与视觉状态分别记账；已关闭视觉项有对应参考/我方截图和版本，未采项不计完成。 |
| **4 漫画/视频** | 在样例可用时验证加载、呈现、翻页/播放、缩放/全屏、错误与退出。 | 自动测试和真实样例验收分开通过；素材缺失保留待验收。 |
| **5 音频** | 播放、章节切换、进度、后台续播、焦点与媒体键。 | 音源和适用设备完成端到端验收；模拟器无法证明的硬件项不能销账。 |
| **6 阶段收口** | 整理提交、CI、截图、外部验收及遗留风险，重排下一阶段开放项。 | Active、Git、CI/QA 与专题证据一致；所有未完成项有负责人、阻塞和下一步。 |

### 阶段 1 主流程验收矩阵

| 子流程 | 必测状态/交错 | 数据验收 |
|---|---|---|
| 搜索 | 正常流式、分页、无结果、网络失败、取消、再次搜索、跨源重复 | 结果状态和去重范围与已确认语义一致，旧会话不污染新会话 |
| 书架 | 空/有书、加书、移除、刷新、分组/排序、从书架开书 | 加入记录、书籍 URL、来源和 UI 列表一致，无重复/幽灵项 |
| 目录 | 本地命中、网络抓取、空目录、失败、刷新、重定向、相对分页 | 章节 URL 和顺序正确，刷新不丢阅读位置，缓存清理符合已确认语义 |
| 正文/翻章 | 正文缓存/未缓存、上下章、快速连翻、失败后重试、章节边界 | 当前章节、正文、下一章预览和阅读进度始终属于同一本书/当前请求 |
| 换源 | 预拉命中/未命中、抓取失败、用户取消、重复点击、换源后续读 | 事务前失败/取消不污染 DB；完成后目录、来源、章节和进度映射一致 |
| 保存/恢复 | 阅读中保存、切后台、退出、重启/重进 | DB 中进度与书架展示、重进章节和阅读位置一致 |

## 7. 跨轨、DB、视觉和素材专项流程

### FFI/API

只有现有接口无法满足已确认需求时新增 API。契约先写清方法、输入/输出、错误语义、Mock 形状与兼容策略；双轨评审后实现。codegen 产物和 native library 必须成套更新，确认 Dart/Rust hash 一致后再进行真实 FFI 验证。

### 数据库/缓存

记录旧数据来源和受影响字段 → 准备旧 schema fixture → 设计事务/迁移 → 覆盖新装和升级 → 注入迁移/写入失败 → 核对备份恢复与关键行 → 评审不可逆风险。缓存清理同时核对 DB、内存状态和重新开书行为。

### UI 一比一

建立屏幕×状态清单 → 同条件采参考版截图 → 采我方截图 → 逐项登记布局、层级、间距、形态、文案、颜色、字体和状态 → 按主题槽位修复 → 重新采图 → 主 Agent 对照并销账。深色参考未采集时标“待采集”，不得从浅色主题推断深色颜色。

### 书源/规则与网络

基于真实源候选选择单一能力 → 固定输入响应 → 对照 Android 对应实现/已确认语义 → 单点修改 → 运行 parser/QuickJS/网络 fixture → 统计受影响源和未覆盖行为。网络测试走本地 loopback；真网站只用于可选外部验收。

### 外部素材

包括 WebDAV 账号、可用音频源、漫画/视频样例、触发段评/验证码/倒计时/外链的书源、皮肤 ZIP、真机媒体键，以及可选的脱敏书架 JSON。按对应阶段插入验收；素材未到时继续离线验证，真实环境项保持“待用户素材”。不保存或写入真实账号凭据到仓库文档。

## 8. 验收证据格式

每次 Agent 交付按以下格式回报：

```text
任务编号 / HEAD / 分支：
根因或实现目标：
修改文件：
测试命令与结果（含退出码）：
CI 链接或运行 ID：
设备/包/变体（如适用）：
截图、日志、DB/fixture 证据路径：
提交号：
未完成范围与阻塞：
```

关闭报告必须区分“代码已交付”“CI 已通过”“设备/素材已验收”。缺一项就保留对应待办状态，不允许把三个状态混写成一个“完成”。
