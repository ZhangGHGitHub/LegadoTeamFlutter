## 系统概述

Legado 项目采用多语言、多构建系统的混合架构，依赖管理通过各语言生态的标准工具协同实现：Android/Kotlin 使用 Gradle Version Catalog，Flutter/Dart 使用 pub 包管理器，Rust 使用 Cargo workspace，Web 前端使用 pnpm。所有锁文件均提交至版本控制，确保构建可重现性。

## 核心系统与工具

### Android/Kotlin 依赖管理
- **版本目录**: `gradle/libs.versions.toml` 集中管理所有依赖版本，包含 Kotlin 2.4.10、AGP 8.13.2、OkHttp 5.4.0、Room 2.8.4 等核心库
- **版本别名**: 通过 `alias libs.plugins.*` 引用插件版本，避免重复声明
- **依赖分组**: 使用 `[bundles]` 组织相关依赖（如 coroutines、androidTest）
- **特殊处理**: 对 jsoup、commons-text 等存在兼容性问题的库使用 `//noinspection NewerVersionAvailable` 注释锁定版本

### Flutter/Dart 依赖管理
- **包管理**: `flutter_legado/pubspec.yaml` 声明直接依赖，`pubspec.lock` 锁定精确版本
- **FFI 桥接**: 通过 `flutter_rust_bridge: ^2.7.0` 与 Rust 核心交互
- **SDK 约束**: 要求 Dart SDK >=3.8.0 <4.0.0，Flutter SDK >=3.38.4

### Rust 工作区依赖管理
- **Workspace 配置**: `rust/Cargo.toml` 定义 8 个 crate 的工作区结构
- **共享依赖**: `[workspace.dependencies]` 统一管理 serde、tokio、thiserror 等常用库版本
- **锁文件**: `Cargo.lock` 确保依赖树完全确定

### Web 前端依赖管理
- **包管理器**: `modules/web/package.json` + `pnpm-lock.yaml` 使用 pnpm 9+ 和 Node.js 20+
- **技术栈**: Vue 3.5.12、Element Plus 2.14.3、Vite 5.4.8

## 架构与约定

### 版本锁定策略
- **严格锁定**: 所有 lockfile（pubspec.lock、Cargo.lock、pnpm-lock.yaml）均提交到 Git
- **选择性升级**: 通过 Dependabot 每周自动检查更新，但保留手动审核流程
- **兼容性保护**: 对已知不兼容的库添加注释说明，防止意外升级

### 依赖来源管理
- **Maven Central**: Android/Kotlin 依赖主要来源
- **Pub.dev**: Flutter/Dart 包管理
- **crates.io**: Rust 包管理
- **Google Storage**: Cronet 原生库动态下载
- **本地 JAR**: `app/cronetlib/` 目录包含预编译的 Cronet 组件

### 构建系统集成
- **Gradle 任务**: `downloadCronet` 任务负责从 Google Storage 下载指定版本的 Cronet 库
- **MD5 校验**: 下载的 SO 文件生成 MD5 并写入 `assets/cronet.json` 进行完整性验证
- **多 ABI 支持**: 同时支持 armeabi-v7a、arm64-v8a、riscv64、x86、x86_64 架构

## 约束与规范

### 强制约束
- **版本同步**: Kotlin、KSP、AGP 版本必须保持兼容（通过版本目录统一管理）
- **依赖最小化**: 通过 R8/Rules 移除未使用的类和资源
- **安全扫描**: Dependabot 定期检查安全漏洞和版本更新

### 开发约定
- **新增依赖**: 优先添加到版本目录而非直接声明版本号
- **版本升级**: 需要测试兼容性后再更新，特别是 jsoup、commons-text 等历史问题库
- **私有依赖**: 通过 `fileTree(dir: 'cronetlib', include: ['*.jar', '*.aar'])` 方式引入本地二进制库

### 自动化维护
- **Dependabot 配置**: 针对 gradle、github-actions、npm 三个生态设置每周更新检查
- **PR 限制**: 每个生态最多同时打开 5 个更新 PR
- **分组更新**: Kotlin 和 KSP 相关依赖合并为 kotlin_KSP 组统一更新
