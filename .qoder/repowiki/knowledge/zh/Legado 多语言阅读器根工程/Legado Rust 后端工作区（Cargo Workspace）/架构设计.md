采用 Cargo workspace 管理 8 个 crate，依赖方向自底向上严格单向：
- `legado-core` 为无内部依赖的基础层，定义公共类型、错误（LegadoError/LegadoResult）、模型（models/）与工具模块。
- 中间层 `legado-parser`、`legado-net`、`legado-js`、`legado-book`、`legado-db` 各自专注单一职责并仅依赖 core。
- `legado-ffi` 作为 cdylib/staticlib 出口，通过 flutter_rust_bridge 生成 Dart 绑定，聚合所有业务 crate 暴露给 Flutter。
- `legado-server` 是独立 axum HTTP 服务，依赖 core/db/net/parser/js，提供 REST + WebSocket + MCP 端点。
- 依赖方向严格单向：ffi → {core,db,net,parser,js,book,server}，server → {core,db,net,parser,js}，各中间层互不依赖。
- `legado-js` 通过 feature flag `quickjs` 条件编译 QuickJS 引擎，默认使用 StubJsEngine 回退。
- `legado-db` 使用 Repository 模式封装 rusqlite，Connection 通过 tokio::sync::Mutex 包装以支持异步共享。
