精确书名源样例：思兔阅读、多看阅读、笔趣阁、无极小说、塔读、宜搜…（见探针日志）。

> 重构 Flutter UI 本轮自动化曾误入「书源管理」（截图 `fair_fl_*.png` 底栏「全选 0/1」），**不能**当作书搜索结果；以引擎探针为准。

## 4. 对比口径（勿夸大）

| 对比 | 原版 | 重构 | 解读 |
|---|---|---|---|
| 全库搜书聚合顶条 | **~336 源** | （UI 本轮未可靠采到） | 原版体感「很多源」 |
| 快速书源引擎精确出源 | （分组未粘，无单独数） | **19** | 相对 219 仍稀 |
| 漫画组（历史报告） | 聚合 ~13 | 精确源 17（2.0.31） | 漫画侧已接近 |

粗算：原版全库同书聚合源数 / 968 ≈ **35%**；重构快速组精确出源 / 219 ≈ **9%**。数量级仍差一截。

## 5. 结论

**部分解决（未解决「普通书源明显偏少」的体感）。**

- 已修好的相对 URL、`class.xxx`、分组粘性、同书聚合等，是**全类型**能力，漫画验收充分，普通书源**间接受益**，但**没有**证明与原版小说搜索出源量对齐。  
- 以「斗破苍穹」证据：原版顶条聚合 **~336**；重构快速组引擎精确出源 **19**。差距大。  
- 本轮**未**交付针对普通书源出源量的新修复，**未** bump 安装。剩余主因方向：大量文本源 JS/Rhino/`jsLib`/反爬（含 Cloudflare WebView）在 QuickJS+纯 HTTP 下失败、仅 page=1、站点失效等——需单独开「文本源搜索对齐」批次，不能用漫画探针宣称已解决。
